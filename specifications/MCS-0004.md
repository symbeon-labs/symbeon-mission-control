# MCS-0004

## Mission Control Protocol

### Version 1.0 – Semantic Operations

---

# 1. Introduction
Mission Control is not accessed via basic CRUD operations. It is accessed via Semantic Operations (The Mission Control Protocol - MCP). This protocol defines how external systems, AI agents, and frontends communicate with the Governance Graph.

# 2. Semantic Actions

## 2.1 Core Operations

### `CreateObject`
- **Intent**: Introduces a new entity into reality.
- **Payload**: `type`, `attributes`.
- **Constraint**: Must immediately evaluate initial policies.

### `UpdateObject`
- **Intent**: Modifies the state or attributes of reality.
- **Constraint**: Triggers `LiveGovernance` re-evaluation. Logs an `Object Event`.

### `RelateObjects`
- **Intent**: Defines the explanation between two realities.
- **Payload**: `sourceId`, `targetId`, `relationType`.
- **Constraint**: Cannot create circular dependencies (except for informational relations).

### `SubmitEvidence`
- **Intent**: Proves reality.
- **Payload**: `objectId`, `evidenceType`, `hash`/`url`.
- **Action**: Wraps `CreateObject (Evidence)` and `RelateObjects (PROVES)`.

### `EvaluatePolicies`
- **Intent**: Forces a manual synchronous check of the Governance Score.
- **Returns**: Array of `Violations` and `Governance Score`.

### `GenerateKnowledge`
- **Intent**: Triggers the extraction of institutional intelligence from a `Completed` object.
- **Action**: Spawns a `Knowledge` object and links it via `DERIVES_FROM`.

### `ArchiveObject`
- **Intent**: Gracefully retires an object from the active operational graph while maintaining it in the historical graph.

# 3. Execution Contracts
When an AI agent (or external system) calls the Protocol, it is bound by the **Architectural Laws (MCS-0001, Chapter 0)**. A failure to provide evidence in `SubmitEvidence` will result in a Protocol-level rejection, not a database error.
